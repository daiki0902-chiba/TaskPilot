# 残課題のA・B・C分類と次の操作

2026-11-23更新：この表は凍結した受入専用版の履歴です。販売者は個人、将来の取得先はGitHub private、有料証明書は現段階で購入しません。次の作業は[通常版中心の移行計画](../development/NORMAL-DEVELOPMENT-ja.md)を参照してください。この表の専用ホスト・署名契約を通常版のローカル検証へ持ち込みません。既存の停止措置は維持します。

**判定はNOT_READY。一般版・独立テストモード・受入版の公開停止を維持する。** この表の完了や計画用JSONの変更で起動を許可しない。mainと実ユーザーデータは変更対象にしない。

分類は主担当で分けた。Aはコードと自動試験、Bは開発者本人の意思決定・契約・権限設定、Cは対象OSの実際の操作である。例えば署名方式はBで選び、その方式との連携コードをAで作り、取得から起動までをCで確認する。一つの分類だけでは実機開始にならない。

## B：開発者が用意・決定するもの

| 項目 | まず決めること | 費用の有無 |
| --- | --- | --- |
| B-1 販売者・発行者 | 個人、個人事業主、法人のどの区分で販売するか。購入者に表示する発行者名の方針 | 方針を決めるだけなら無料 |
| B-2 署名提供元・本人確認・鍵管理 | 対象資格と、TaskPilotが要求する署名を扱える方式。提供元の正式画面で本人確認する | CA証明書、トークン/HSM、クラウド署名は通常有料。**現段階での購入は保留** |
| B-3 限定配布先・担当者 | 新しいprivateリポジトリ、または個別招待したDropbox等。publicのTaskPilotは変更しない | 無料枠で足りれば追加費用なし。容量・利用量・権限機能はプラン次第 |
| B-4 端末と利用権 | Windows 10/11の検証端末、実Excelの有無、試験担当者 | 既に正規ライセンスを保有していれば追加購入不要。未保有なら条件次第 |

## C：開始条件を満たした後のWindows 10/11実機操作

| 項目 | 対象PCで確かめること | 開始条件 |
| --- | --- | --- |
| C-1 正式な取得・導入 | 招待制の取得、版・ハッシュ・発行者、Windows保護有効での導入、Main前の改変防止 | Aの必須実装とBの正式署名・配布先が成立していること |
| C-2 GUI前の安全性 | 既定のホスト・DLLロード・取得元情報・固定合成保存先・リンク保護・バックエンド検査 | 対象キットの専用検査が実装済みで、保護を変更せず成功すること |
| C-3 アプリの機能 | GUI、タスク、サブタスク、工数、進捗、月次確定、定期処理、通知、Excel、バックアップ・新DBへの復元 | そのPCでの専用事前検査が明確に起動許可を返すこと |
| C-4 再起動・失敗時の記録 | 合成データ保持、限定診断、停止後の安全な再オープン | 通常データの参照・コピー・ハッシュ採取を行わないこと |

両OSは別々に記録する。今は全項目未実施である。[条件成立後の実機手順](AFTER-READY-ja.md)、[31件の確認表](CHECKLIST-ja.md)、[OS別記録欄](RESULT-TEMPLATE-ja.md)を使う。Windows Serverでの自動試験をWindows 10/11での実機操作の合格にしない。

## 開発者が次に行う操作：優先順

1. **販売者の区分を決める。** まず「個人・個人事業主・法人」のどれかだけを記録する。証明書を購入しない。
2. **受入の取得先を選ぶ。** GitHubの新しいprivateリポジトリか、特定担当者へ招待するDropbox等を選ぶ。空の取得先の準備とアクセス範囲の確認までは可能だが、EXE・配布ZIPはまだ置かない。
3. **使える検証端末を整理する。** Windows 10/11とExcelの有無をメモする。TaskPilotや既存データを開く必要はない。
4. **方式が確定してから対象資格と見積りを確認する。** A-4～A-6の互換性が解決し、提供元が自分の区分を受け付け、必要な署名が可能と確認できてから契約・本人確認へ進む。
5. **署名済みキットの開始判定を待ってCへ進む。** 今ある内部EXEや旧ZIPで代用しない。警告や検査を解除して起動しない。

今の段階で必要な意思決定は、販売者の区分と限定配布先の希望である。署名証明書の購入や実機アプリ起動は次の操作ではない。
