## 推奨する受入専用構成（設計案・未実装）

### 1．専用の入口と用途確認

受入専用のLauncher/EXEを通常版とは別に作る。一般版のInitialize-TPRuntimeの停止、既存のFirstUse検査、一般公開フラグは維持する。GUIを検査するためだけに、それらのfalse/throwをtrueへ変更しない。

専用入口には別の安全条件を設ける。対象バージョン・用途・ソースコミット・全ペイロードのハッシュ・発行者・受入許可の検証が揃わなければ、保存領域を開く前に停止する。用途の表示だけ、改変できるJSONの `approved=true`、環境変数だけの切替は許可情報の代わりにならない。未許可・改変・引数なし・不正引数でも通常版へ戻らない設計を検証する。

通常版TaskPilot.exeを包んで現在の停止を迂回するだけのランチャーにはしない。共有GUIと保存層を再利用する場合も、受入専用の入口からモードを固定し、通常モード・通常移行への到達不能性を検証する必要がある。

### 2．ペイロードと保存先

| 同梱・記録するもの | 条件 |
| --- | --- |
| 受入専用Launcher/EXE・設定 | 初心者のダブルクリックで専用検査から始まり、通常起動の選択肢なし |
| Runtime・保存ブローカーDLL・専用の入口 | ハンドル相対I/O、非空ガード、ファイル保護を維持 |
| Storage・System.Data.SQLite管理DLL・x64 native DLL | メモリーDB、authorizer、writer所有、復旧検査を維持 |
| Codec DLL・ImportExcel/EPPlus・必要なAdapters/schema/Assets | 起動時にコンパイル・依存取得を行わない。全一覧は生成時に確定し、過去の147ファイル等を流用しない |
| ビルド／用途マニフェスト・全ファイル一覧・署名 | 対象コミット・build ID・配布物・試験証跡を結び付ける。ハッシュのみを発行者証明にしない |
| 手順・確認表・結果票・第三者表示と必要な対応ソース | 業務データや古いテストDBは同梱しない |

保存先は既存の固定テスト名前空間と新規IDへ限定する計画。環境変数・設定・コマンドラインから任意のルートを受け付けない。弱い既存ACL、古いマーカー、リンク、回復sidecar、未完了チェックポイントは既存どおり停止し、変更して採用しない。新しいWindowsユーザーやVMを、この未実装を回避するための必須手段にはしない。

### 3．最初の実機試験とGUIの順番

1. 専用版と署名・取得経路・許可情報を検証する。
2. GUIを開かず、そのWindows 10/11上の新規合成領域で必要な安全性試験を行う。
3. 全必須検査が成立した場合だけ専用GUIを開く。提案する表示名は `READY_FOR_DESKTOP_ACCEPTANCE`。**現行にこの状態は未実装**で、一般配布許可でもGUI合格でもない。
4. [31件の確認表](CHECKLIST-ja.md)を実施する。初回GUIの成功を先に仮定しない。
5. Windows 10/11それぞれの結果・署名・取得元・保存先・再起動後状態をレビューする。合格しても一般販売の判定へ自動昇格しない。

現在の `BLOCKED`、`PACKAGE_CHECK_ONLY`、過去の `READY_FOR_ISOLATED_TEST` をこの状態へ読み替えない。リンク作成などの権限が足りず正例試験が成立しない場合も成功扱いにしない。管理者実行・開発者モード・ポリシー変更を要求して通す方法は使わず、未達として記録する。

### 4．配布とブロック問題

第一の実証候補は、正規署名されたユーザー単位インストーラーにペイロードを内包する方法。未実装の設計候補であり、署名さえあればSmartScreenや現在のDLL取得元チェックを通るとは保証しない。通常ブラウザーで取得し、保護有効のWindows 10/11で導入・ロード・更新・終了後データ保持を実証する。

限定した受入の候補は、アクセス管理した非公開保管先や、取得者が権限を持つGitHubの非公開な配布経路等。現在のリポジトリはpublicなので、ActionsのArtifactだけでは取得者を担当者に限定できない。具体的な配布先・提供者の署名証明書・署名済み成果物は今回確認できておらず、作成・公開していない。秘密鍵をチャットへ提出する運用も要求しない。

MOTW/ADSの削除、ブロック解除、Defender/SmartScreenの無効化、除外登録、実行ポリシー変更、自己署名ルートの登録、別の取得方法で取得元情報を避ける案内は行わない。拒否されたら停止・記録する。

## エラーと既存データの扱い

現行の独立ログ採取は停止中。今使えるツールとして案内しない。現在はケースID・時刻・画面に出たエラー・PC条件を手動記録する。将来の専用採取も受入IDのLogsと限定メタデータだけとし、DB・CSV・JSON・Excel・バックアップを自動収集・アップロードしない。

通常データを持つ同じユーザーでの安全性は、実業務ファイルの前後ハッシュでは証明しない。開発者が新規作成した合成の通常領域のハッシュ・構造・関連だけを検査する。実際の通常版GUIはデータを読み得るため同時起動しない。競合検査は合成の通常保存層を保持するプロセスで行い、実際の通常GUIとの同時動作は未検証と記録する。
