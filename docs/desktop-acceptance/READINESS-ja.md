# 実機受入の開始条件と現在の判定

**判定：NOT_READY。Windows 10/11の実機で起動してよい受入専用EXE・ZIPは未提供。** 専用入口・許可検査・起動前検査のコードを追加しても、発行元・署名・配布・対象PCでの事前安全性検査の条件が揃うまで起動を許可しない。一般版と独立テストモードの公開停止を維持する。

実装開始点はDraft PR #1の`88e565a5aa5dd3ee88b2af7e289524648e899049`。mainと実ユーザーデータは変更対象にしない。実データの存在検査、読み込み、コピー、ハッシュ採取も行わない。

## 実装と使用許可を分ける

受入専用の`TaskPilot.Acceptance.exe`は、通常版`TaskPilot.exe`を包んで停止を外す入口ではない。C#ランチャーへパッケージ保護と信頼する発行元の情報を組み込み、専用のPowerShell/WinForms入口を検査してから実行する。通常モード・移行・任意の保存先を選ぶ引数は設けない。

専用検査が`READY_FOR_DESKTOP_ACCEPTANCE`を返さなければGUIへ進めない。現在は信頼する発行元が未設定で、許可情報と署名済み配布物がなく、Windows 10/11上の事前安全性検査の実装も不足している。**有効な開始許可を返せる構成ではない。** チェック値や環境変数の手変更でこの条件を通す運用はしない。

一般版のRuntime、既存の独立検査・ログ採取、一般公開フラグは停止したまま。内部コンパイル結果を受入用キットとしてダウンロードさせず、CIへ保存するのは検査報告だけとする。

## 専用構成の安全条件

詳しい実装ファイル・処理順・残課題は[受入専用ビルド実装記録](../12-desktop-acceptance-build.md)に記載する。

- 信頼する発行元と設定のハッシュをC#ランチャーへ固定する。未設定なら外部スクリプトやユーザー保存先を開く前に停止する。起動時に外部C#をコンパイルしたり、未検査DLLを先にロードしたりしない。
- 受入用途、版、期限、環境IDとペイロードのハッシュを署名済み許可情報へ結び付ける。JSONの真偽値や環境変数だけを許可として扱わない。
- 内容を読む前にリンク・ハードリンク・パスとファイル保護を検査し、利用中はハンドルを保持する。新パッケージガードの基本Native検査に加え、ファイル・ディレクトリーのその場書換えに対する追加の対抗試験が必要。ハッシュ一致や基本検査だけで安全性を保証しない。
- 自作コードは固定した発行元のAuthenticodeを検査する。元のベンダーDLL・モジュールは再署名せず、固定依存から生成した`acceptance/vendor-code-lock.json`と、用途署名済みペイロードで原本のハッシュを確認する。
- 専用検査は許可された入口、Windows 10/11 Desktop5.1 x64、.NET、配布物、対象PC検査を必要とする。現在不足する対象PC検査を合格へ置き換えない。
- 起動できる段階でも、保存先は`%LOCALAPPDATA%\TaskPilotAcceptance\<署名済み環境ID>`と専用用途マーカーに限定する。通常独立モードの`TaskPilotTest`とは別にし、任意のルート、通常版への切替、既存データの移行は受け付けない。
- 診断は固定スキーマのコード・真偽値・版などに限定する。通常ログ・例外全文・タスク名・個人名・ユーザーのパス・DB・Excel・バックアップを自動で集めず、自動送信しない。

## 配布方式と保護設定

正規署名したユーザー単位インストーラーに必要なペイロードを内包する方法を実証候補とする。現在、正式な署名証明書、署名済み導入物、アクセス制限した取得先は用意されていない。EXE設定や依存探索など、CLRが`Main`前に処理する内容もOSで改変を防ぐ必要があり、現在のメタデータ変更拒否ACLだけでは不足する。署名があってもSmartScreen、MOTW、DLLロードが成功するとは仮定しない。通常ブラウザーから取得したものをWindows 10/11で保護有効のまま検証する必要がある。

取得元情報の削除、ブロック解除、ウイルス対策の無効化・除外登録、実行ポリシー変更、自己署名ルートの登録、管理者起動による検査通過は案内しない。秘密鍵をチャットへ提出する運用も要求しない。拒否された場合は停止する。

現在のリポジトリはpublic。public ActionsのArtifact名に「受入専用」と付けるだけでは取得者を制限できない。一般候補・独立モード・受入EXE/ZIPの公開は停止し、報告だけを保存する。

## 既存データと証跡

通常領域の前後比較には、開発者が新規作成した合成データだけを使用する。試験者の実業務ファイルを読んだりハッシュを採ったりしない。通常GUIは既存データを読み得るため同時起動しない。競合試験は合成の通常保存層を保持するプロセスで行い、実際の通常GUIとの同時動作は未検証とする。

[既存のServer CI 45000222885](https://github.com/daiki0902-chiba/TaskPilot/actions/runs/45000222885)では通常8群、独立27件、追加保存8件、安全停止12項目、リンク80試行・ガード40項目が成功した。これは専用入口の追加分やWindows 10/11の実機GUIに対する結果ではない。専用入口の新しい試験結果は[実装記録](../12-desktop-acceptance-build.md)へ分けて残す。

**現在の実機GUI開始判定はNOT_READY、一般配布再開は不可。** コード追加、内部コンパイル、自動試験の成功だけで「実機で起動してよい」とは案内しない。
