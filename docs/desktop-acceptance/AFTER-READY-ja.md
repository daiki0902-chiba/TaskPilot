# 条件成立後の実機確認（現在は実行不可）

**この手順は将来用。現在の判定はNOT_READYであり、ダウンロード・インストール・起動を開始しない。** 実在する署名済み受入キットが完成し、その版に対応する配布URL・発行者・インストール方法・検査手順を発行してから具体的な操作を確定する。未完成のコマンドや仮の保存先をそのまま実行しない。

## 0．開始前の確認

1. 開発者が指定した受入版・対象コミット・ハッシュ・発行者・使用期限の組が揃っていることを確認する。一般版や過去のArtifactで代用しない。
2. 正式な導入方式が、Windows保護を変更せずに、PowerShellホストの互換性・Main前のファイル保護・DLLロード・保存先分離を満たしていることを確認する。
3. 検証するOSを記録する。Windows 10と11は別の結果票を使う。Serverの合格結果を転記しない。
4. 使用する文字列や日付は[確認表](CHECKLIST-ja.md)に定めた合成データだけにする。既存のDB・CSV・Excel・バックアップをコピーしたり、既存データのハッシュを採ったりしない。

## 1．取得とインストール

開発者から個別に許可された取得先へサインインし、指定された版だけを取得する。一般公開URLや古いダウンロードを探して代用しない。配布時の日本語説明に従って、表示された発行者・署名・版が指定内容と一致することを確認する。

インストーラーの方式と実際の画面は未確定のため、現在はクリック手順を発行できない。発行者不明、署名不正、SmartScreen・ウイルス対策・組織ポリシーの拒否があれば停止する。「詳細情報から実行」、ブロック解除、実行ポリシー変更、ルート証明書の追加、除外設定、管理者でのアプリ起動を解決策にしない。

## 2．GUIより先の検査

その版に同梱された受入専用の事前検査を、正式に指定された入口で実行する。今ある独立モード検査の引数を外して通す方法は使わない。

確認対象は、そのPCのOS・ホスト互換性・署名・取得元・インストール保護・合成保存先・リンク境界・SQLiteの検査である。必要な正例が権限不足で成立しない場合も停止する。**全必須条件に合格し、受入専用の起動許可が明示された場合だけ次へ進む。** コア試験の`BACKEND_PROBE_PASSED_GUI_BLOCKED`はGUI起動許可ではない。

失敗時には画面に出た固定エラーコードとケース番号だけを記録する。Windowsの設定、環境ID、設定ファイル、許可情報の手編集で合格に変えない。

## 3．GUIと保存機能

正式な受入専用入口から起動し、タイトルの`[ACCEPTANCE ONLY] [TEST MODE]`と「合成データのみ」の表示を確認する。表示が違えば操作を進めない。

[31件の確認表](CHECKLIST-ja.md)に従い、新規タスク・編集・状態変更・削除、サブタスク、日別記録と完了実績、稼働・月次値、定期処理、通知、Excel3冊とグラフ、バックアップ・新DBへの復元を順に確かめる。実Excelでの表示とグラフ確認は、ファイル構造だけを調べる自動試験とは別に記録する。

通常版は既存業務データを読む可能性があるため、比較や同時起動のために開かない。保存先は受入専用領域だけを使う。通常版の設定やバックアップは参照しない。

## 4．終了・再起動・限定診断

アプリを終了して同じ受入入口から再起動し、作成した合成データが保持されることを確認する。新しいテスト環境を勝手に選んで再現しない。

診断が必要な場合はアプリを終了し、その版で許可された専用の採取入口を使う。出力に含めるのは固定コード・件数・版等だけとする。通常ログ、例外全文、利用者名を含むパス、DB、設定JSON、Excel、バックアップを送らない。自動アップロードは行わない。

別のアプリや診断が使用中なら停止し、ロックを削除したり強制解除したりしない。復元や障害時の操作で既存データへ切り替えない。

## 5．結果を残す

[OS別結果票](RESULT-TEMPLATE-ja.md)へ、実際に行った項目だけを合格・不合格として記録する。できなかった項目は理由付きで未検証とする。スクリーンショットに個人情報や業務画面を含めない。

どちらかのOSの未実施、不合格、保護機能による拒否が残れば、その状態を保ったまま開発者へ返す。一般版の公開停止や販売判定は、受入担当者の操作で変更しない。
