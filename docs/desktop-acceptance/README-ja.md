# TaskPilot 0.4.0.2 実機受入の準備ガイド

**現在はアプリを起動しないでください。実機受入用として許可されたEXE・ZIPは、まだありません。** 一般版・独立テストモードの公開停止を維持したまま、受入専用入口の実装を進めています。専用入口も開始条件が不足しているため`BLOCKED`です。この手順書があることは起動許可を意味しません。

今できるのは、PCの条件と試験計画の確認です。後半のアプリ操作は、安全な専用ビルドと起動前検査が提供された後の計画として記載しています。一般販売・一般配布の再開とは別に判断します。

実装中の専用版は、通常版や従来の独立モードと別の`TaskPilotAcceptance`保存領域を使う構成です。ただし、この名前のフォルダーを自分で作ることは起動許可になりません。署名、OSによる導入物の保護、対象PCでの事前安全性検査、パッケージへの追加対抗試験などが未達です。終了後に診断を安全に採取し直す手順も未実装のため、専用採取入口は停止しています。

## 今できる準備：アプリは起動しない

### 1．判定表を読む

[開始条件と未達条件](READINESS-ja.md)を先に確認します。「開始不可」「BLOCKED」「未達」が残っている間は、TaskPilotを実行しません。[機能確認表](CHECKLIST-ja.md)も、今は操作せずに読みます。

GitHub Actionsの緑色の結果は、Windows Serverでの自動試験が成功したことを示します。自分のWindows 10/11で、EXE・画面・通知・Excelが動いたという意味ではありません。

### 2．Windowsの種類を確認する

1. スタートメニューから「設定」を開きます。
2. 「システム」→「バージョン情報」を開きます。
3. Windows 10またはWindows 11、エディション、バージョン、OSビルドを控えます。
4. 「システムの種類」が64ビットであることを確認します。

Windows Server、32ビットWindows、ARM環境で代用して合格にしません。表示が分からない場合は「不明」と記録し、アプリ起動へ進みません。

### 3．Windows PowerShellを確認する

1. Windowsキーを押しながらRキーを押し、「ファイル名を指定して実行」を開きます。
2. `powershell.exe -NoProfile` と入力してEnterを押します。通常権限で開き、管理者として実行しません。`-NoProfile`は個人の起動スクリプトを読み込まない指定で、保護設定を変更するものではありません。「Windows PowerShell (x86)」「ISE」「PowerShell 7」は今回の確認用には選びません。
3. 次の内容をコピーして貼り付け、Enterを押します。PCの情報を画面へ表示するだけで、TaskPilotの保存先を調べたり変更したりしません。

```powershell
$PSVersionTable.PSVersion
$PSVersionTable.PSEdition
[Environment]::Is64BitProcess
Get-ItemProperty -LiteralPath 'HKLM:\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full' -Name Release | Select-Object Release
```

| 表示 | 確認する値 |
| --- | --- |
| PSVersion | `5.1`から始まる |
| PSEdition | `Desktop` |
| Is64BitProcess | `True` |
| .NET Framework Release | 値をそのまま記録。4.8以上を推奨。4.8の目安は`528040`以上。実際の開始可否は専用ビルドの指定条件で判定 |

赤いエラー、値の欠落、想定と違う表示が出た場合は、その内容を控えて停止します。管理者でやり直したり、設定変更や追加インストールで検査を通したりしません。

### 4．試験環境のメモを作る

Windows 10とWindows 11では記録を分けます。既存のTaskPilotフォルダーを開く、データをコピーする、バックアップを作り直す、既存ファイルのハッシュを採る操作は行いません。

| 記録する項目 | 記入例・注意 |
| --- | --- |
| 試験するPC | 自分で区別できる呼び名。公開したくないPC名は不要 |
| OS | Windows 11、版、ビルド、64ビットなど |
| PowerShellと.NET | 上の画面に表示された値 |
| 画面 | 解像度と拡大率。設定の「システム」→「ディスプレイ」で確認 |
| 入力 | 日本語IMEを使用するか。設定を変更しなくてよい |
| Excel | 既に分かっている製品名・版、未導入、または不明。確認のために業務ファイルを開かない |
| TaskPilotの既存利用 | 「利用中」「未利用」「不明」の申告だけ。保存先や内容の確認はしない |
| 現在の判定 | 「専用受入ビルド未提供のため開始不可」 |

PC条件のメモが揃っても、アプリの試験開始条件を満たしたことにはなりません。

## ここから先は将来の計画：専用ビルドの提供後だけ行う

**以下を今実行しないでください。専用入口の実装と、使用許可された配布物の提供は別です。** 発行元の設定、署名済み許可情報、安全な配布方式、Windows 10/11上の事前安全性検査などが未達です。一般向けの公開停止を外したEXEや、手作業で設定を書き換えたものは受入ビルドとして使いません。

### 5．受入用キットを受け取る

担当者から、次が揃ったキットを受け取る計画です。

- 「実機受入専用・販売用ではない」と分かる名称と表示。
- 正確なソースコミット、ビルドID、EXE/DLLを含む全ファイルの一覧・ハッシュ。
- 発行元を確認でき、Windowsの保護を解除せずに扱える配布方式。
- 一般起動へ流れない専用の起動入口と、受入用の起動前検査。
- 検査対象のビルドとテスト環境IDに結び付く、受入専用の許可情報。
- 日本語手順、機能確認表、停止時に提出する情報の説明。

メールやチャットで「試してよい」とだけ言われた場合も、これらがないまま起動しません。ZIPと同じ場所にあるハッシュ文字列だけでは、発行元を確認したことにはなりません。

### 6．展開して起動前検査を行う

1. 担当者が指定した配布元・ビルドIDと、受け取ったものが一致するか確認します。
2. エクスプローラーの「すべて展開」で、新しい専用のフォルダーへ全体を展開します。EXE単体を取り出さず、既存TaskPilotのフォルダーへ上書きしません。
3. この段階でTaskPilotのEXEをダブルクリックしません。ZIPの展開先と、アプリのデータ保存先は別です。展開先を変えただけでデータが分離したとは判断しません。
4. 正式なキットに同梱された「受入用の起動前検査」だけを、そのキットに記載された方法で実行します。**現在の検査ツールを変更して代用しません。**
5. OS・PowerShell・.NET、全ファイル、署名と取得元、受入許可、テスト環境ID、全保存先の分離が確認できるまで、アプリへ進みません。

専用入口は **`READY_FOR_DESKTOP_ACCEPTANCE`** を確認できなければGUIを開かない設計です。**現在この開始許可を返せる構成はありません。** 対象PCで実施する事前安全性検査の仕組みが不足しているため、専用検査も`BLOCKED`で停止します。`BLOCKED`、`PACKAGE_CHECK_ONLY`、過去の`READY_FOR_ISOLATED_TEST`などを、開始許可へ読み替えません。

WindowsがEXE・DLL・スクリプトを拒否した場合は停止します。署名があることだけで起動可能と判断しません。セキュリティ警告を無視する、ブロックを解除する、ウイルス対策の除外へ登録する、保護設定を変更する操作は行いません。

### 7．許可された入口から、架空データだけで確認する

専用入口が実装・検証され、起動前検査が開始許可を返した場合に限り、その入口から起動する計画です。本書には現時点のアプリ起動コマンドを掲載しません。

起動できたら、最初に次を確認します。

- タイトルに`[ACCEPTANCE ONLY]`があり、画面内にも実機受入専用・合成データ専用であることとIDが表示される。`[TEST MODE]`だけの既存入口で代用しない。
- 検査で示されたID・専用保存先と画面の表示が一致する。
- 通常版のタスクや設定が表示されず、移行・引き継ぎ・自動復元の案内も出ない。
- 通常版へ切り替える操作がない。

どれかが違った場合は入力せず停止します。通常版のタスクが出た場合も、内容を調べたり編集・削除したりしません。

確認作業は[機能確認表](CHECKLIST-ja.md)の順番で行います。タスク名は`UAT-`から始めるなど、すべて架空のものに統一します。業務用のタスク、CSV、JSON、DB、設定、Excel、バックアップを取り込みません。

バックアップと復元も、その受入環境で作った合成データだけを使用します。通常版の保存先・設定・バックアップを探す操作はしません。通常版のハッシュや構成の比較は、開発者が用意した合成の通常領域で実施する項目です。試験者の実データへ同じ検査を行いません。

### 8．結果を記録して終了する

各項目は「合格」「不合格」「未実施」「停止」のいずれかで記録します。Serverで成功した項目も、自分のPCで実施していなければ「未実施」です。

Excelの生成と、実Excelで開いて表示を確認する作業は分けて記録します。開く場合も受入環境で作成した架空のブックだけを使います。Excel自身の履歴や自動回復などは外部アプリの動作であり、TaskPilotの保存先分離と別に扱います。

終了後も、テスト用フォルダーを手作業で削除しません。通常版の保存先の整理・名前変更・移動も行いません。再開時は、承認されたキットに記録した同じテスト環境IDを使う計画です。実際の再開方法は、将来の専用キットに記載されるものだけを使います。

## エラーや想定外の画面が出た場合

1. それ以上の登録・編集・復元をやめます。繰り返し起動して通そうとしません。
2. 時刻、ビルドID、試験項目、直前に選んだ操作、画面に出た`TP-ACCEPTANCE-`等のエラーコードを控えます。タスク名・個人名・業務内容・ユーザー名を含むパスは書き写しません。
3. 画面を残す場合は、業務情報・ユーザー名などが映っていないか確認します。業務データが表示された場合、その内容を提出しません。
4. 診断採取は、その専用キットで安全性を確認した採取方法が提供された場合だけ使います。実行中の専用診断は許可されたコードと件数などだけを扱い、通常ログやエラー全文の収集には使いません。終了後の安全な採取は未実装で、専用入口も`BLOCKED`です。**現在、利用許可されたキットはありません。既存の独立ログ採取も停止中**です。
5. TaskPilotのDB・CSV・JSON・バックアップ・業務Excelを提出しません。ログを自動でアップロードしたり、公開リポジトリへそのまま添付したりしません。

実行拒否、署名不明、ハッシュ不一致、許可情報の不一致、保存先不明、通常データの表示、保存・復元失敗は、いずれも開始・継続不可です。安全検査を外して成功扱いにしません。
