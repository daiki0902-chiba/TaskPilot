# 受入専用ビルド：実装と安全停止

**Windows 10/11で実行してよい受入専用EXE・ZIPは未提供。判定はNOT_READY。** 一般版・独立テストモードの公開停止を維持し、Draft PR #1の開発ブランチへ専用入口と検査を追加する。mainと実ユーザーデータは対象外。

この変更は、実機受入へ進むためのコードと停止条件を用意するもの。信頼する署名者、署名済み許可情報、保護を有効にした配布の実証、対象Windows上でGUI前に行う安全性検査が不足するため、内部コンパイル結果を試験者へ渡さない。

## 入口と信頼の順番

通常版`TaskPilot.exe`と別の`TaskPilot.Acceptance.exe`を使用する。専用パッケージへ通常版のEXE・起動スクリプトを含めず、通常起動・移行・任意の保存先を選ぶオプションも設けない。

1. ネイティブのC#ランチャーが引数を限定する。受け付ける操作は専用GUIへの要求、`--preflight`、`--collect-logs`だけ。GUI要求でも前段の全検査が必要。
2. ランチャーへ固定した発行元と信頼設定を確認する。発行元が未設定の現在は、外部PowerShellやユーザー保存先を開く前に停止する。
3. ファイルの内容を読む前にパッケージのリンク・パス・保護を検査し、利用中のハンドルを固定する。先に外部の未検査DLLをロードしてから、そのDLLで自分自身を検査する構成にはしない。
4. 自作の外部スクリプトやDLLのAuthenticode、固定した発行元、ペイロード一覧、取得元条件を確認する。署名は有効な信頼チェーンを必要とし、ハッシュ一致だけを発行元の証明にしない。元のベンダーDLL・モジュールには自作発行元の再署名をせず、固定した依存から生成する`acceptance/vendor-code-lock.json`と、用途を署名したペイロードマニフェストの組合せで原本のハッシュを確認する。
5. 専用用途・版・期限・環境ID・ペイロードを結び付けた署名済み許可情報を検査する。許可なし・改変・期限切れは停止する。`approved=true`や環境変数で代用しない。
6. 専用起動前検査が対象Windows、PowerShell、.NETとGUI前の安全性検査を確認する。**対象Windows上の事前安全性検査を実行する専用ランナーが不足しており、現在ここからGUIへ進む許可は出せない。**
7. 将来すべての条件を満たした場合だけ、署名済み許可情報のIDを用いて既存の保存ブローカーとメモリーSQLiteを初期化し、専用GUIへ進む。

`READY_FOR_DESKTOP_ACCEPTANCE`は専用入口が要求する状態名で、現在この状態を返せる構成はない。一般版の`TP-ISOLATION-BLOCKED`、既存検査の`BLOCKED`、CIの一般公開停止を外す処理は加えない。

この順番で保護できるのは`Main`到達後のパッケージ利用である。CLRが`Main`より先に読むEXE設定や依存の探索は、ランチャー内の検査だけでは保護できない。OSが改変を防ぐ署名済みの導入方式が必要で、現在のメタデータ変更拒否ACLだけでは開始条件を満たさない。

## 保存先と既存データの保護

専用起動では通常版のLocalAppData配下を存在検査・読み込み・コピー・ハッシュ採取しない。許可情報の検査と起動前検査に失敗した場合は、LocalAppDataの取得や専用保存先の作成にも進まない。

起動できる段階では、`CreateAcceptance`を使い、通常の独立モードとも異なる`%LOCALAPPDATA%\TaskPilotAcceptance\<署名済み環境ID>`という固定名前空間と専用の用途マーカーを使用する。DB、設定、通知、定期処理、月次値、Excel、バックアップ、ログ、一時ファイル、ロックをその配下に揃える。既存独立モードの`TaskPilotTest`は維持し、従来27件の回帰試験と分ける。任意のルート指定・環境変数経由の切替・通常モードへの変更は受け付けない。通常版データの移行や復元は実行しない。

リンクや弱い保護、古いマーカー、未完了チェックポイントは既存の停止条件を維持する。受入専用GUIの表示は`[ACCEPTANCE ONLY]`と合成データ専用の案内を用い、通常版と区別する。表示だけで分離を証明したことにはせず、実装と自動試験の対象にする。

## 診断に含めるもの・含めないもの

実行中の専用診断は固定スキーマを使い、許可したイベントコードと件数、版など必要最小限の情報に限定する。例外全文、ユーザー名を含むパス、タスク名・備考、既存の通常ログ、DB、CSV、JSONの業務設定、Excel、バックアップは自動採取しない。自動アップロードも行わない。

アプリ終了後の環境を安全に開き直して診断を採取する手順は、まだ実装されていない。専用採取入口は`TP-ACCEPTANCE-DIAGNOSTIC-NOT-READY`で停止する。コードのみのイベント記録を実装したことを、完成した診断採取キットとして案内しない。

画面を手動で提出する場合も、ケースIDとエラーコードに限定し、個人情報や業務画面を含めない。[初心者向けガイド](desktop-acceptance/README-ja.md)に従い、利用許可された専用キットがない間は診断コマンドを実行しない。

新しい専用入口の結果は、従来の保存境界の結果と分けて記録する。現時点の文書作成時には、新しい専用入口を含むCI結果は未確定。未実施を成功と報告しない。

| --- | --- |
| 既存保存境界：通常8群・独立27件・追加保存8件・安全停止12項目 | 既存[Windows Server CI 45000222885](https://github.com/daiki0902-chiba/TaskPilot/actions/runs/45000222885)。新入口追加前の証跡 |
| 新しい許可検査・不正引数・専用入口の安全停止 | 新規実行結果を確定後に記録。現段階では未検証 |
| 専用パッケージ・診断の制限・既存機能の回帰 | 新規実行結果を確定後に記録。現段階では未検証 |
| 新パッケージガードのファイル・ディレクトリーのその場書換え攻撃 | Nativeの基本検査と分け、さらに対抗試験が必要。現在の検査だけで境界の完全性を証明しない |
| Windows 10 GUI・通知・実Excel・保存・復元 | **未検証、開始停止** |

| 正規署名・ブラウザー取得・DLLロード・更新 | **未検証、開始停止** |

CIが成功した場合も、Windows Serverで実施した内容とLinux上の静的・拒否試験を明記する。ServerのWinFormsコントロール生成やExcelブック構造の検査を、Windows 10/11での実際の画面操作やExcel閲覧へ読み替えない。

## 配布の判断と残課題

**一般配布・独立テストモード・受入EXE/ZIPの公開停止を継続する。** 内部のEXEを生成できても、一般向けArtifactや受入用ダウンロードとして公開しない。報告Artifactはアプリのキットではない。

実機GUIを始める前に次が必要である。

1. 信頼する正式な発行元を定め、署名済みランチャー・スクリプト・DLL・許可情報を用意する。秘密鍵をチャットへ提出しない。
2. パッケージ保護と取得元チェックを満たす導入方式を実装・実証する。CLRが`Main`前に読む設定・依存もOSの保護で改変できない必要がある。正規署名したユーザー単位インストーラーが候補だが、現在は未完成で、メタデータACLだけでは代用できない。
3. 対象Windows上でGUI前に実行する安全性検査のランナーを実装し、保護設定を変更せず必須試験を成立させる。権限不足の正例試験をSKIPして合格へ変えない。
4. 取得者を実際に制限する配布先を用意する。public ActionsのArtifactは限定配布の代わりにならない。
5. 対象コミット・バイナリー・全試験の証跡を固定し、[開始条件](desktop-acceptance/READINESS-ja.md)を満たしたうえで、正式なダウンロードと起動手順を確定する。
6. パッケージガードのファイル・ディレクトリーその場書換えに対する対抗試験と、終了後の限定診断を安全に開き直す手順を完成させる。

未署名のまま使う、取得元情報を消す、Windowsの警告を解除する、ポリシーや保護設定を変える、古いEXEへ引数を付ける方法は提供しない。現在は初心者へダウンロード・起動コマンドを案内できない。
