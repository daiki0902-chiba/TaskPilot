# Windows 10/11 受入テスト項目

この文書は実施手順であり、合格記録ではありません。Windows 10 x64、Windows 11 x64で別々に[結果記録](RESULT-TEMPLATE-ja.md)を作成してください。両OSの初期状態はすべて「未実施」です。

この33項目は通常の初回試験を基本とします。独立モードは [TEST-MODE-ja.md](TEST-MODE-ja.md) の実施条件・起動コマンド・必須14項目を先に確認し、同じIDのテスト領域で合成データだけを扱います。既存業務ユーザーで今すぐ実行してよいという案内ではありません。通常の `-FirstUse` を外すだけで独立モードの試験にしません。

Windows Server 2022 / Windows PowerShell Desktop 5.1で、同梱System.Data.SQLiteを使う自動試験8群と旧保存処理の回帰試験、未署名0.4.0.1 EXE・候補ZIPの生成が成功しています。一部のテスト専用改変フックはnative試験でSKIPでした。これは、Windows 10/11でのEXE起動、画面・通知・実際のExcel出力を確認した結果ではありません。同梱の `Evidence` 内の記録と[Serverの証跡](https://github.com/daiki0902-chiba/TaskPilot/blob/development/sqlite-commercial-20261116/docs/verification/README.md)を参照してください。

上記は従来候補の記録です。0.4.0.2の独立境界・合成通常領域不変・実Excel生成は、当該キットの `Evidence/windows-isolated-mode-results.json` を確認し、従来版の結果から推定しません。

## 最初に確認すること

1. [起動README](README-ja.md)でモードを決めます。通常の初回試験は、業務データが存在しない専用標準ユーザー/VMで実施します。独立モードは対象ビルド・自動試験・レビュー・実機受入の条件を確認した担当者が、専用ガイドの `-TestMode -TestEnvironmentId` を使います。
2. パッケージ、BuildInfo、EXE、OS情報、試験者、日時、保存先を結果記録へ転記します。同じ配布物のハッシュで両OSを試します。
3. 事前検査で不足・改変・DLLブロックが見つかった場合は起動せず「ブロック」と記録します。この試験のためにUnblock-File、システム設定変更、管理者起動は行いません。
4. 既存のTaskPilotフォルダーの削除・名前変更・上書き、業務データのコピー、実DBへのSQL実行は行いません。`LOCALAPPDATA`の環境変数だけを付け替えて隔離したことにはしません。
5. 画面の保存後は、関連する一覧・詳細・Excelを確認し、通常終了と再起動で同じ値が残ることを確認します。エラーがあれば[ログ採取](LOGS-ja.md)に従って記録します。

「合格」は操作、期待値、再起動後の保存、証跡を確認できた場合だけです。「対象外」は理由を必須とし、DLLブロックで到達できない機能を対象外や合格へ変更しません。不合格の後も同じDBを操作し続けて症状を隠さず、証跡を残してください。

## 入力する合成データ

すべて架空の値を使います。試験日を `D`、その月を `M` とし、各タスクの実際のIDを結果記録へ控えます。

| 呼称 | 入力例 | 主な用途 |
| --- | --- | --- |
| T1 | `UAT-受入A_日本語 ' " ; SELECT`、優先度「高」、状態「対応中」、実施予定日・作業開始日・期限をD、予定所要時間5.01h、備考`=1+1` | 文字・日付・小数工数、サブタスク、日別記録 |
| T2 | `UAT-受入B_別タスク`、優先度「低」、状態「未着手」、予定所要時間0.00h、実施予定日・作業開始日を未指定 | 親子の分離、検索、未指定値 |
| T3 | `UAT-受入C_完了実績`、予定所要時間2.00h、実施予定日・作業開始日・期限をD | 完了日と申告実績1.25h |
| T4 | `UAT-受入D_削除専用`、予定0h。架空のサブタスクと、前月の日付の0.25h日別記録を1件ずつ追加 | 削除確認のキャンセルと承諾。当月合計へ混ぜない |

GUIの予定所要時間はスピナーが0.25h刻みですが、5.01を直接入力して保存を確認します。日別作業記録のGUIは最小0.25hなので、0.75hと0.26hの2件で合計1.01hを確認します。0.01hの日別記録をGUIで入力できるとは案内しません。タスク名・備考の入力欄は単一行なので、改行の保持は別途合成データ移行・開発側試験の対象です。

| F03 | 既知のエラーまたは正常な診断試行後、LOGS手順でログと環境情報を採取する。 | エラー全文・操作・時刻・項目ID・版・OS・必要なログを関連付ける。業務データやDBを自動添付せず、合成データの証跡だけを保管する。 | 採取一覧、結果記録、再現手順 |

F01/F02は通常試験の配布物・DBでは実行しません。ディスク満杯や強制終了の試験を日常利用PCのシステムドライブで行わないでください。失敗試験に到達できない場合、Serverの自動試験で代用したことにせず未実施として残します。

独立モードのB01は、そのIDのBackupから選ぶ固定一覧です。通常版や他IDのDBを選びません。復元後の別名DBも同じテスト領域に作り、元テストDBを残します。X02/X03のため試験者が別途Excelを起動した場合は、Excel自身のMRU・自動回復など、TaskPilotの境界外で生じる動作を記録します。

期待するブック構成は次のとおりです。CompletedTask.xlsxにも分析シートがあるとは案内しません。

| ブック | シート・図の確認対象 |
| --- | --- |
| TaskList.xlsx | TaskList、作業記録、サブタスク、月間稼働、月別分析、タスク工数比較。月別の予定稼働率、稼働可能時間と日別記録、タスク別の予定・進捗・完了実績のグラフ。 |
| CompletedTask.xlsx | CompletedTask。完了タスク、完了日、申告実績などのメタデータ。 |
| Dashboard.xlsx | Dashboardと未アーカイブのTaskList。アーカイブ済みタスクがある場合のみCompletedTaskシートも対象。ステータス割合・未完了優先度のグラフと集計値。 |

移行用の旧データや祝日CSVはこのキットに含めません。旧データ移行は別工程で合成fixtureを準備してから実施し、業務原本を代用しません。C04とR03の営業日ケースは別途確認済み試験CSVが必要です。準備できない場合は該当部分を未実施として残します。

## 終了時

TaskPilotとExcelを通常終了し、結果記録と合成データの証跡を保管します。試験後にTaskPilot4や旧TaskPilotのフォルダーを自動削除しません。両OSの必須項目にブロック・不合格・未実施が残る間は販売合格と判定しません。詳細な開発側確認は[既存のWindows受入表](https://github.com/daiki0902-chiba/TaskPilot/blob/development/sqlite-commercial-20261116/docs/build/WINDOWS-ACCEPTANCE.md)も参照してください。
