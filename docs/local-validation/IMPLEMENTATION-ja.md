# ローカル検証専用の実装と現在の限界

**2026-11-23の追加方針変更により、この専用版の開発は凍結しました。** 現在は[通常版中心の最小構成](../development/NORMAL-DEVELOPMENT-ja.md)へ移行します。以下の専用親ホストを完成させることを、通常版ローカル検証の前提にしません。既存の起動拒否は維持します。

**NOT_READY。クリーンなWindows実機でTaskPilotを操作できる環境は、まだ完成していない。** 有料証明書は購入しない方針を反映したが、その代わりに既存の検査を解除する実装は行っていない。

設計上の第一候補は、新規のWindows VM内で開発者本人が確認済みソースから作る専用ビルドである。[安全性の前提](DESIGN-ja.md)、[初心者向け環境準備](ENVIRONMENT-ja.md)、[決定事項](DECISIONS.json)を参照する。普段の業務ユーザーや、共有ディスクへ到達できるだけの別ユーザーを安全な代替とはしない。

## 追加したコード

| 対象 | 変更 |
| --- | --- |
| Runtimeブローカー | 固定の`TaskPilotLocalValidation/<環境ID>`、専用マーカー、`CreateLocalValidation`／`OpenExistingLocalValidation`、専用読取ロックを追加 |
| SQLite所有タグ | ローカルDBだけ別の所有タグを使い、同じIDの独立・受入DBのコピーも拒否。既存タグ・スキーマは維持 |
| ローカル入口 | 通常版・正式受入版とは別の`TaskPilot.LocalValidation.exe`と専用GUIを用意。現状は親ホストの証明不足で終了コード2を返す |
| GUI接続 | 既存GUIから生成し、ローカル用Runtime・画面表示・内容を含まない診断を接続。`IsAcceptance`を偽装せず、ローカル専用属性を使う |
| 事前検査 | ファイルやユーザー保存先へ進む前に専用ホストを要求。現状は常に`NOT_READY`、GUIへ進む経路なし |
| 整合性検査コア | アプリ固有の一時RSA鍵によるレシートの署名、用途・版・ソース・期限・VM/ユーザー束縛、ファイル一覧・ハッシュ・保持ハンドル・取得元を検査。成功しても起動許可は出さない |
| 内部ビルド | 通常版・正式受入版の入口を混入させず、必要な依存を同梱。入力の取得元情報を削除せず、ブロックされた入力は拒否。EXEはCI内の拒否試験用だけで配布ZIPを作らない |
| 異常終了検査 | 合成データの子プロセスをコミット前後で実際に終了させ、保存値と再オープンを確認。未完了チェックポイントは自動修復せず保存・停止する |

## 有料証明書なしで確認できる範囲

アプリ自身が固定した公開鍵と検証コードにより、ローカル生成物の変更・用途・期限・対象環境の相違を検出することはできる。これはOSが信頼する発行者署名ではなく、VMの清浄性や正しいソースであることの独立した証明にもならない。

証明書ストア登録、信頼ルート追加、実行ポリシー変更、取得元情報削除、認証マネージャーの無効化は行わない。既存の正式署名検査も変更しない。現在の外部PowerShell方式ではRestricted／AllSignedを解決できず、既存ポリシーが許可しない場合は停止する。Bypassをローカルモードの許可条件にも使わない。

## 未完成である安全上の機構

1. ホスト側で新規VM・ディスク・共有/転送なしを確認し、ゲストへ安全に対応付けるプロトコル。
2. 信頼するローカルビルド親が、子のCLR起動前からEXE設定・DLL・全スクリプトを固定し、終了まで保持する仕組み。
3. 生存する親とのチャレンジと受領した範囲を照合する入口。真偽値、環境変数、自己申告のマーカーで代用しない。
4. OS設定を変更せず、実際のWindows 10/11で外部スクリプトと依存の読み込みを成立させるホスト互換性と正規のソース移送・生成手順。

`TaskPilot.LocalValidation.Host`と事前検査を常時停止にしているのは、この不足を合格に置き換えないためである。形式上RSA検証を通すテスト用のHostFactsを作っても、本番側の入口は許可されない。将来のセッション実装では、複数回取得・解放の所有権管理も必要になる。

## 検証と実機の判定

Linuxではレシート12ケース・88検査、専用入口41検査、拒否9検査、計画47検査、同梱構成172検査が合格した。PowerShellとC#5の構文も確認した。これはWindowsでの動作結果ではない。

方針変更前の[Windows Server CI 45139980609](https://github.com/daiki0902-chiba/TaskPilot/actions/runs/45139980609)は成功しました。通常8群・独立27件・追加保存8件・既存受入検査と、専用の検証7群が合格しました。専用起動はNOT_READY、アプリ起動なし、実ユーザー領域へのアクセスなし、EXE/配布ZIP公開なしです。[当時の専用版レポート](../verification/local-validation-paused-20261123.json)を保存します。Windows 10/11のGUI、通知、実Excel、実際のクリーンVMとOS保護は未検証のままです。以後はこの専用版を既定CIで再ビルド・再検査しません。

**現在はローカルGUIの起動手順を提示しない。** 次に開発者が行えるのは、ホストのWindowsエディション・仮想化機能・利用権を確認し、業務データのない新規VMを準備できるかを整理することまでである。既存の業務VMや通常版データを持ち込まない。有料証明書の購入を待つ必要はなく、残りは上記のコードと実環境の検証である。
