# 無償のローカル検証方式：安全設計と成立条件

**設計上は条件付きで成立する。現在のWindows 10/11での起動許可を意味しない。** 有料の公的コード署名がないことと、検証を省略することを同一視しない。一般版・独立テストモード・従来の受入版の停止措置は維持する。

以下は採用候補の設計であり、VMのホスト側作成証跡、生存する信頼済み親との起動プロトコル、Windows 10/11の正例検証を完了したという報告ではない。準備・隔離・暗号検査のコアを実装しても、その不足を真偽値で埋めてGUIを開始しない。

対象は、開発者本人が管理するクリーンなゲストWindowsの中で、確認済みソースから生成するローカル検証物に限定する。配布先のWindows利用者が発行者を信頼するための仕組みとは、目的と信頼の出発点が異なる。

## 比較と採用候補

| 方式 | 無料で行える範囲 | 安全上の限界・判定 |
| --- | --- | --- |
| 普段使うWindowsユーザーの別フォルダー | 保存先を分けるコード試験 | 誤起動や未捕捉のI/Oで業務データへ到達し得る。ローカルGUI検証の基盤に採用しない |
| ホスト上の専用Windowsユーザー | 新しいプロファイル、標準ユーザーでの検証 | 共用ドライブ、ネットワーク、クリップボード等を排除した証明にはならない。単独では十分でない |
| 新規のオフラインWindows VM | 既存のホスト業務データを持ち込まない環境、再現可能な合成データ | 仮想化ホスト・OS・作成手順を信頼する必要がある。共有機能を別途排除し、既存ポリシーが起動を許す場合の採用候補 |
| OSで信頼しない自己署名証明書 | アプリ自身が固定した鍵で改変を検出する用途 | 公的発行者の証明やWindowsの署名信頼、Restricted/AllSignedの成立を代用できない |
| 一回限りのアプリ用RSA署名 | ローカル生成物の一覧と用途・範囲を結び付ける検証 | OSの信頼設定を変えず実装可能。署名鍵を自分で作れることは、開発者やソースの真正性の証明ではない |

第一候補は**新規のオフラインVMでのローカルビルド＋生存するビルド親プロセスによるファイル固定＋VM/利用者に限定した一回限りの署名記録**である。自己署名証明書を証明書ストアへ登録する方式は採用しない。

## 信頼するものと、証明できないもの

信頼の出発点は、開発者が確認したソースと、そのソースをローカルにコンパイルするクリーンな開発環境である。最初のビルド用EXEを、未検証のダウンロード物として実行してはならない。

次のものは自動判定だけでは証明できない。

- ゲストがクリーンであり、マルウェアが存在しないこと。
- VMの機種名や製造元の文字列が本物で、ホストの共有機能がすべて無効であること。
- 自己生成した署名鍵が正しい開発者に属すること。
- 管理者や同一ユーザーが任意コードを実行できる環境で、悪意ある改変を永続的に防ぐこと。
- ソースを改造した第三者による配布を技術的に完全防止すること。

VMの識別情報、ネットワークドライブ、実行ポリシー等の検査は、前提に矛盾する環境を拒否するために使う。`clean=true`という設定やVMの機種名だけを起動許可にしない。意図しない別環境での実行は範囲の結び付けで拒否するが、その性質を公的な発行者認証と呼ばない。

## VMの前提

ホスト側で新しく作成したWindows 10/11のゲストを使う。通常利用するVMの複製、業務用ディスク、ホストユーザープロファイルを引き継ぐVMは使わない。

- ゲストに正規のWindows利用権があること。仮想化機能が無料でも、OSライセンスまで常に無料になるわけではない。
- 新しいゲストディスクと検証専用ユーザーだけを使用する。
- ホストドライブの転送、共有フォルダー、拡張セッションのクリップボードやドライブ転送を使わない。
- 検証中はネットワークを切り離す。必要なソースと固定依存ファイルだけを読み取り専用メディア等で持ち込む。
- ホストや通常版からDB、CSV、設定、Excel、バックアップ、ログを持ち込まない。
- OS保護、ウイルス対策、実行ポリシー、信頼ルートを変更しない。OSが拒否すれば停止する。

これらはホストの実際の構成を操作して確認すべき事項であり、ゲストの自己申告ファイルでは代用しない。自動テストの合格だけを理由に、この前提を成立済みにはしない。

## PowerShell実行ポリシーの前提

既存の標準ホストは外部`.ps1`・`.psm1`を使用する。現在の有効ポリシーを読み取り、そのままの設定で実際の必要ファイルが許可される場合だけ先へ進む。

- `Restricted`ではこの方式を許可しない。署名の有無では解消しない。
- `AllSigned`も、OSの信頼設定を変更しない自己署名だけでは成立しないため許可しない。
- 既に`RemoteSigned`または`Unrestricted`であるクリーンな開発用環境でも、取得元情報・必要なスクリプト・モジュールの実行可否を個別に確認する。ポリシー名だけでGUIを許可しない。
- この候補では`Bypass`、`Undefined`、未知のポリシーを許可しない。既存設定がそうなっていることを検査の省略理由にしない。
- `Bypass`を設定したり、認証マネージャーを差し替えたり、別経路でスクリプトを渡したりしてファイル検査を回避しない。
- 取得元情報は消さない。取得元ブロックがあれば、Gitやコピー等を解除手段として案内しない。

従って、**クリーンなWindowsクライアントの既定Restrictedをそのまま維持する条件では、現行の外部スクリプト方式によるGUI起動は成立しない**。この場合はNOT_READYを維持する。別の実行方式を導入するには独立した設計・実装・検証が必要である。

## ローカル生成物の真正性と固定

最初のローカルビルド用プログラムは、開発者が確認したソースから、そのゲスト内の信頼するコンパイラーで作る。固定したコミット、明示的なソース一覧、依存ファイルの元ハッシュを検査する。Gitのコミット文字列を引数で受け取るだけでは、作業ツリーの内容の証明にならない。

ビルド用親プロセスは新しい検証物を完成させた後、子プロセスを起動する**前**に、次のすべてを固定する。

- 子EXEと`.exe.config`。
- マネージドホスト、ブローカー、Codec、SQLiteのマネージド・ネイティブDLL。
- 全PowerShellファイル、モジュール、設定用の配布ファイルとマニフェスト。
- ファイルまでの全ディレクトリーチェーン。

固定ではリンクやハードリンクを内容の読取り前に拒否し、書込み・削除を共有しないハンドル、メタデータ保護、空でない固定ディレクトリー、一覧の完全一致を要求する。親は子の終了までハンドルを保持する。

これは、CLRが子の`Main`より前に読む設定や依存ファイルの差替えを、子自身の検査だけで防いだと誤認しないためである。最初の管理されたビルド親プロセス自体については、クリーン環境でのローカル生成という信頼の出発点が必要であり、自分自身を検査するだけでは補えない。

## 一回限りの署名記録

公開用の証明書検査を無効にするのではなく、別のローカル専用用途として、アプリが固定した公開鍵による署名を検査する。

- 秘密鍵は名前のない一時鍵としてメモリーだけに保持し、証明書ストア、永続キーストア、配布物、Artifactsへ保存しない。
- 公開鍵を子の固定ビルドへ結び付け、検査対象から読み出した任意の公開鍵をそのまま信頼しない。
- 署名記録は用途`LocalDeveloperValidationSyntheticOnly`、版、ソース、環境ID、ビルド乱数、期限、全ペイロードのハッシュ、VM・マシン・ユーザーの範囲に結び付ける。
- マシンGUIDやSIDの生値をログへ出さない。必要な範囲の照合は内部で行い、外へ出すのは成否コードだけにする。
- コピーしたEXEを単独で起動しても許可しない。ビルド親との生存するセッションと新しいチャレンジを要求し、環境変数、真偽値、古い記録だけで代用しない。

この署名はローカル生成物の整合性と誤配布時の拒否を支える。Windowsが自己署名を公的に信頼したこと、SmartScreenや組織ポリシーの許可、販売可能性の証明にはならない。

## 保存先と旧データの隔離

ローカル専用入口は固定の`TaskPilotLocalValidation/<環境ID>`等の名前空間と専用の用途マーカーを持つ。通常版、旧独立モード、従来受入版のルートを取得・移行・復元しない。任意ルート指定や内部の通常モード切替も設けない。

DBの所有タグもローカル専用にする。ディレクトリーだけを分け、従来の環境IDだけで識別すると、同じIDのDBを持ち込んだ際に別用途のデータを採用してしまうおそれがある。バックアップ、新DBへの復元、再オープンも用途タグを要求する。

GUI、通知、月次値、稼働設定、Excel、ログ、バックアップ、一時ファイル、ロックまで既存ブローカーの隔離枝へ接続する。独立モードのDBだけを変更して完了とはしない。画面は`[LOCAL DEVELOPER VALIDATION]`等で区別し、正式な受入版とは別のフラグにする。

終了後の診断は読取専用の既存ロックと上限付き読取りを使い、固定イベント件数のみを返す。異常終了時のチェックポイントは保存し、自動削除・自動復旧で試験を続けない。

## 必須の拒否と検証

通常ホスト、別VM・別ユーザー、期限切れ、署名・ハッシュ不一致、余分なファイル、未知の親、親の終了、取得元ブロック、拒否される実行ポリシー、共有・危険なパス、別用途DB、ロック競合は安全停止する。

既存の通常8群、独立27件、保存8件、受入版の既存検査を削除しない。ローカル用には次を追加する。

1. 親が固定する前、子のCLR起動前、検査後、起動中の差替え拒否。
2. 親の強制終了、古いセッション再利用、コピー・別環境起動の拒否。
3. 同じ環境IDでも通常・独立・受入・ローカルの相互採用拒否。
4. 新しいローカル領域での全保存機能と、固定件数だけの診断。
5. 保存失敗・途中チェックポイントの保持と、旧環境へのフォールバック禁止。

Windows Server上の自動検査は実装の検証であり、Windows 10/11のクリーンVM、既存ポリシー、GUI、通知、実Excel、保護機能有効での初回起動の代用にはならない。必須の正例が成立しない場合は未検証やSKIPを合格へ変更せず、NOT_READYにする。

## 判定

有料証明書を待たずに進められるのは、別用途のローカル生成物、暗号学的な一覧検査、生存する親の固定、専用保存先と拒否試験の実装である。クリーンVMの前提と、変更していないOSのポリシーが許すことは別に必要である。

特にRestricted環境や未確認の共有状態を、自己署名や設定マーカーだけで許可する設計は成立しない。これらの前提を確認できず、または親の固定を含む起動経路が完成しない段階では、安全なGUI起動手順を発行しない。
