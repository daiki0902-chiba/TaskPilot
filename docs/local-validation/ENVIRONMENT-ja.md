# 有料証明書を使わないローカル検証環境の準備

**現在の実機開始判定はNOT_READY。ここにGUIの起動許可はない。** 有料コード署名証明書は現段階で購入しない。一般版・独立モード・既存受入版の公開停止を維持し、ローカル専用版もEXE・配布ZIPをpublic Artifactsへ出さない。将来の限定取得先はGitHub privateリポジトリとする。

ローカル方式の候補は、開発者が管理する新品のWindows仮想マシン内で、確認済みソースから検証専用プログラムをビルドする方式である。VMの情報や「クリーンです」というチェックだけでは、マルウェアや共有先がないことを証明できない。ホスト側での作成履歴と、開発者本人の管理を安全性の前提にする。

## 方式の比較

| 方式 | 分離できる範囲と制限 | 今回の扱い |
| --- | --- | --- |
| 新しいWindows 10/11 Hyper-V VM | 新しい仮想ディスクとゲストユーザーを用意し、ホスト共有・転送・ネットワーク等を使わなければ実データを持ち込まず管理できる。作成元や設定の確認はホスト側で必要 | 優先候補。ゲストOS、機能、権利の確認と実機検証が必要 |
| 同じPCの専用標準ユーザー | 他ユーザーの保護されたプロファイルとは分かれるが、共有ディスク・共有フォルダー・外部ドライブ・共通設定までは分離しない | これだけで安全なクリーン環境とは扱わない。今回のGUI開始手順には採用しない |
| 普段の業務ユーザー | 実データや設定へ到達する可能性がある | ローカル専用版を起動しない |
| Windows Sandbox | 閉じると内容が破棄されるため、終了後の再起動・保存保持・障害復旧の継続試験と相性が悪い。既定でネットワークが有効で、共有・転送設定にも注意が必要 | 今回の継続GUI受入の代用にしない。設定を追加しただけで検証済みとはしない |
| 開発用の自己署名証明書 | アプリ自身が公開鍵を固定し、その鍵で作ったデータの整合性を調べることは可能。ただしWindowsが信頼する発行者にはならない | OSの信頼ストアへ登録しない。RestrictedやAllSigned、SmartScreen、組織ポリシーの許可にはならない |

今回のアプリ内RSAレシートは、ローカルビルドの内容・用途・実行範囲を確認するためのもの。公的な発行者証明、クリーンなVMの証明、OSの実行許可とは別である。最初の親ホストは、開発者本人がクリーンなVM内で確認済みソースから作ったものを信頼の起点にする。配布された未署名EXEを信頼の起点にしてはいけない。

## 1．必要なWindows環境と費用

- 検証対象はWindows 10/11 Desktop x64。両OSは別々に確認する。
- Hyper-Vのホストには対応エディションと仮想化対応ハードウェアが必要。Microsoftの要件ではWindows 10/11 ProfessionalまたはEnterpriseが対象であり、Homeで同じ手順が使えるとは扱わない。
- Hyper-Vが使えるPCを保有していても、ゲストWindowsを使う権利は別途確認する。ホストのライセンスがゲストの利用まで自動的に許可するとは考えない。
- Windows 11 Enterpriseには公式の90日評価版の案内がある。本人確認・利用条件・期限・用途の制約を確認し、継続利用や販売用ライセンスの代わりと決めつけない。
- 有料コード署名証明書を使わなくても、Windows・仮想化ホスト・実Excel等が未保有なら別の費用が発生し得る。今回の計画ツールは購入や契約を行わない。

Windowsの機能追加や再起動が必要な場合は、開発者が利用端末の権限と影響を確認して判断する。Hyper-Vを有効にするツールはこの変更から自動実行しない。アプリを管理者として起動して検査を通す方法は使わない。

## 2．クリーンなVMの作り方

これは環境準備の候補手順であり、現在のTaskPilotを起動する手順ではない。

1. ホストにHyper-Vが既に利用可能か、対応エディション・ハードウェア・利用権を確認する。未準備ならここで止まり、別のPCやライセンスも含めて決める。
2. Hyper-Vマネージャーで「新規」→「仮想マシン」を選び、検証専用と分かる名前を付ける。既存の業務VM、業務用VHD、業務VMのチェックポイントを再利用しない。
3. 検証専用の新しい仮想ディスクを作る。ホストのデータディスクや物理ディスクを渡さない。必要容量・メモリー・世代は、選んだ正規Windowsメディアの要件に合わせる。
4. 正規のWindowsメディアを使用して新規インストールする。ネットワーク接続は「未接続」を基本とする。ライセンス認証やOS・開発ツール準備で通信が必要なら、先にホスト側の手順・取得元・時点を決め、TaskPilotの検証時に外部ネットワークや業務ネットワークを接続しない。
5. ゲストには検証専用ユーザーを用意する。業務アカウント、個人のクラウドドライブ、メール、ブラウザー同期、既存のTaskPilotを設定しない。新しいユーザーを作っただけで共有先までなくなるとは考えない。
6. VMConnectは基本セッションを使用し、拡張セッションのドライブ・クリップボード・プリンター等の転送を使わない。共有フォルダー、ホストドライブ、ゲストサービスのファイルコピー、追加の業務ディスクを接続しない。
7. ホスト側で、VMの作成元、OSメディア、仮想ディスク、接続設定を確認する。VM名・メーカー表示やゲスト側のマーカーだけで、この確認を代用しない。
8. 業務データを一度も入れていない準備完了状態を記録する。チェックポイントを使う場合も、この新規の検証VMだけを対象にし、業務VMを操作しない。

OSやセキュリティのセットアップ画面に、保護を無効にしないと進まない問題があれば停止する。登録・認証を避ける非公式手順や、既存の業務ユーザーをコピーする手順は示さない。

## 3．必要なファイルと入手方法

必要になるのは、指定コミットのTaskPilotソース、ビルド・検査ツール、固定ハッシュで確認したSQLite/ImportExcel等の依存ファイル、第三者ライセンス・対応ソース、およびその版の検証手順である。通常版のDB、CSV、JSON設定、Excel、バックアップ、ログは一切持ち込まない。

ソースと依存ファイルは正式な開発取得手順と取得元の記録に基づいて用意し、ゲスト内で確認する。**取得元情報を削除したり、別の取得・移送経路へ変えてブロックを避けたりしない。** ホスト共有や実ドライブのマッピングを便利な転送方法として追加しない。取得元情報を保持してクリーンなゲストへ必要なファイルだけ渡す方法は、ローカルビルド手順の一部として確認する必要がある。未確定のISO作成やGit取得を、ブロック解除の代わりとして実行しない。

public ArtifactsのEXEや過去のZIPは使わない。将来のprivate取得先を用意しても、ローカル専用EXEを販売用・購入者向けに配らない。鍵・レシート・環境IDを別環境へコピーして使い回さない。

## 4．起動前検査

検査用のVMでPowerShellを開き、次の情報を読むだけなら、TaskPilotや業務データを開く必要はない。ここではスクリプトファイルを実行せず、設定も変更しない。

```powershell
$PSVersionTable.PSEdition
$PSVersionTable.PSVersion
[Environment]::Is64BitProcess
Get-ExecutionPolicy -List
Get-CimInstance Win32_OperatingSystem |
    Select-Object Caption, Version, ProductType
```

`ProductType=1`がWindowsクライアントであることの一部の確認になる。実行ポリシーは各Scopeの優先順位を含めて判定するので、LocalMachineの値だけで決めない。現行の外部PowerShellファイルを使う方式では、**既存の有効ポリシーがRestricted・AllSigned・Bypass・不明の場合は停止**する。RemoteSigned/Unrestrictedであっても、取得元・モジュール・レシート・VM・親ホスト等の全条件が別に必要である。

検査のために実行ポリシーを変えない。自己署名の登録、発行元の自動信頼、保護の停止、警告を無視する起動で条件を満たしたことにしない。Windowsクライアントの既定がRestrictedなら、今回の条件のまま現在の外部スクリプトを使えるとは判断しない。

計画ツール`New-TaskPilotLocalValidationPlan.ps1`は、指定コミットと新しい環境IDから計画JSONを作るだけであり、起動前検査の合格、VMのクリーン性、署名レシート、実行許可を発行しない。

## 5．TaskPilotの起動

**現在、起動コマンドは提供しない。** 未検証のWindows 10/11 GUIへ進む許可はない。必要な実装・自動試験に加え、ホストの新規VM作成確認、変更していない互換ポリシー、取得元、ローカルビルド、子の起動前からの親プロセスによる全ファイル固定、環境・利用者・期限に結び付くレシートなどが確認された場合に、その版の専用手順を発行する。

将来の画面ではローカル専用の表示を要求し、保存先は`TaskPilotLocalValidation`のその環境ID配下だけとする。`TaskPilot`・`TaskPilot4`・`TaskPilotTest`・`TaskPilotAcceptance`へ切り替えたり、自動移行したりしない。親ホストを閉じて子だけを続ける、別のEXEを直接起動する、引数・環境変数・設定を手編集して許可を作る操作は認めない。

## 6．GUI・通知・Excelの確認

開始許可が発行された後に、合成のタスク・サブタスク・日付・工数だけを入力する。作業記録と完了実績を別に確認し、定期処理・月次確定・通知・カレンダーの結果を記録する。

Excelは、生成ファイルの内容とグラフ構造の自動検査、実Excelでの表示・グラフの手動検査を分ける。実Excelは正規ライセンスのある検証用環境だけで使用する。Excelが未準備なら表示・外部アプリ連携の項目は未検証とする。ホスト側の業務Excelを開いて代用しない。

## 7．保存・バックアップ・復元・異常終了

許可された同じローカル環境で合成データを保存し、終了・再起動後に保持されることを確認する。バックアップと復元はローカル専用領域内で作られたものだけを使い、復元先は新しいDBとする。通常版や受入版のバックアップを持ち込まない。

保存失敗、未完了チェックポイント、ロック競合等の異常時は安全停止を確認し、DBやロックを手で削除・修復・差し替えない。強制終了や電源断の手動検査は、合成専用VMで対象版の手順と復旧条件が発行された後だけ実施する。自動試験の例外注入を、実際の電源断・ディスク満杯試験の合格と同じにしない。

## 8．不具合の記録と報告

OSの種類、TaskPilotの版・コミット、ケース番号、固定エラーコード、期待した結果と実際の結果を記録する。未実施と不合格を分ける。自動採取は、専用の承認済み入口が出すコード・件数等の限定情報だけにする。自動アップロードはしない。

画面に業務内容、利用者名、利用者のパスが映っていれば提出しない。VM/利用者の実識別情報、秘密鍵、認証情報、DB、通常ログ、例外全文、Excel、バックアップをチャットや公開PRへ添付しない。ローカルレシートの有効期限や環境IDを改変して再試験しない。

## 9．終了後の後片付け

TaskPilotと親ホストを通常の終了操作で閉じる。異常があれば、承認されたコードだけの報告を残し、アプリのロックや未完了チェックポイントを自分で削除しない。

VM内の一部フォルダーをホストから再帰的に削除する方法は使わない。検証専用VMを完全にシャットダウンし、Hyper-Vマネージャー上の名前・仮想ディスク・保存場所が今回の新規VMであると開発者本人が確認してから、そのVMだけを管理する。削除が必要なら報告保存と対象確認後に手動で行う。既存の業務VM、ホストのTaskPilot、実ユーザーデータを削除しない。ツールは自動クリーンアップを行わない。

## 公式資料と確認範囲

2026-11-23確認。エディション、機能、ライセンス、評価条件、提供状況は各公式説明と契約を優先する。

- [Hyper-Vのホスト要件](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/host-hardware-requirements)：Windows 10/11 Professional・Enterprise、ハードウェア要件。機能を自動的に有効にしたという意味ではない。
- [Windows Sandboxの概要](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/)：対応エディション、閉じた際の破棄、既定ネットワーク、再起動中の保持の範囲。今回のHyper-V方式の実証ではない。
- [Windows 11 Enterprise Evaluation](https://www.microsoft.com/en-us/evalcenter/evaluate-windows-11-enterprise)：公式90日評価の案内。ゲストの継続利用・販売用ライセンスを無償で保証するものではない。
- [Windows PowerShell 5.1の実行ポリシー](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_execution_policies?view=powershell-5.1)：Restricted/AllSigned等の動作とScopeの優先順位。

有料証明書が不要な設計であっても、現在の実機開始可否は別に判定する。条件が満たされない環境はNOT_READYのままにする。
