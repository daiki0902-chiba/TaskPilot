# VMを使わない通常版の実機検証：調査結果と代替策

2026-11-23。対象はDraft PR #1、調査時点`fa05dffa088ba9a120fd68fd80113951e0f4d5e6`。VMは必須にしない。通常版だけを製品として維持し、独立・受入・ローカル専用版の開発と公開は再開しない。

## 結論と実装判断

TaskPilot自身のファイル保存先を分ける設計は可能だが、現在の機能を維持したまま、普段と同じWindowsユーザー内で個人データへのアクセスや副作用を完全に隔離できる小さな修正は確認できなかった。安全条件を満たしたと見せる保存先引数、環境変数、許可フラグは追加しない。今回はアプリ・保存・移行・復元・製品ビルダーを変更していない。

通常版が使う既定の保存先だけを変えても、以下の経路が残る。

| 経路 | 確認した実装と影響 |
| --- | --- |
| 保存先と別のログ・ロック | `Runtime/TaskPilot.Runtime.ps1:83-87`。RootだけでなくProfileからログとロックを作る |
| 旧データの読み込み | `TaskPilot.ps1:25`、`Adapters/TaskPilot.GuiStartup.ps1:188-195`。旧保存先を別に決定し、引き継ぎ承諾画面より前に内容を検査する |
| 通常・旧版ロック、移行バックアップ | `GuiStartup.ps1:181-183,199-202,209-211`。通常のLocalAppDataを直接使う |
| 復元・CSV入力 | `GuiStartup.ps1:254-263`、`TaskPilot.ps1:294-299`。通常のファイル選択では保存先の外も選択可能 |
| 一時ファイル | `Adapters/TaskPilot.GuiIsolation.ps1:219-221`。通常分岐はユーザー共通のTEMPを使う |
| Excelの外部起動 | `GuiIsolation.ps1:165-186`。登録済み閲覧アプリをStart-Processで起動する。既存Excelへの引き渡し、Officeの履歴・回復・アドイン等はTaskPilotのパス検査では制御できない |

既存ブローカーには固定領域、保持ハンドル、SID/DACL、リンク拒否がある。ただし利用には全IsTestMode分岐、メモリSQLite保存、制限付きファイル選択、Excel処理の一般化が必要であり、単なる保存先変更ではない。停止中の独立モードを別名で再開しない。外部Excelや任意の.NETコードを含めた制限にはOSのプロセス隔離も検討対象になるが、互換性・実装・検証の負担を伴うため今回導入しない。

## 同じPCでの最小の代替策

**新しい標準のローカルWindowsユーザーで、同一の通常版EXEを使う方法を提案する。** VM、別アプリ、保存先切替引数は不要。アプリ本体・GUI・SQLite・バックアップ・復元・競合検出・二重起動処理は共通のままである。

Windowsが返すKnownFolder、TEMP、Officeのユーザー設定が検証ユーザーに分かれ、既知のTaskPilot自動保存先もそのユーザー内になる。既存の業務ユーザーのデータを読み込んだり、ACLやファイルを変更したりして準備しない。任意の開発保存先指定を公開しないため、その引数を経由したパス悪用も追加しない。

これはPC全体のサンドボックスではない。Public、共有、追加ディスク、緩いACL、手動選択ファイル、マシン共通のOfficeアドイン等は残るリスクである。通常版は別ユーザー領域へのアクセスを全面禁止するプログラムではない。共有データの権限・利用環境を確認できない場合、この代替策も開始条件を満たさない。既存データを移動したり権限を変更したりして通過させない。

## 開発者が行える準備（アプリ起動前まで）

以下は専用標準ユーザーを選ぶ場合の手順であり、現在の業務ユーザーでTaskPilotを起動する案内ではない。Windowsのバージョンにより設定項目の名称が異なる。

1. Windowsの「設定」→「アカウント」→「その他のユーザー」（Windows 10では「家族とその他のユーザー」）→「アカウントの追加」を開く。「このユーザーのサインイン情報がありません」→「Microsoftアカウントを持たないユーザーを追加する」で、例えばTaskPilotDevを作る。種類は**標準ユーザー**のままにする。Codexがアカウントを作成する操作は行っていない。
2. スタートメニューのユーザーアイコンから「ユーザーの切り替え」で新しいアカウントへサインインする。runas、管理者としてのアプリ起動、LOCALAPPDATAの差し替えは使わない。
3. 個人・業務ファイルをコピーせず、クラウド同期や業務共有へ接続しない。検証用の架空データと確認済みの開発資材だけを扱う。Officeの確認に個人用文書・マクロ・アドインを持ち込まない。
4. 専用ユーザーのWindows PowerShell 5.1で、次の**システム情報だけ**を確認できる。業務ユーザーのファイルやデータベースを開くコマンドは実行しない。出力を報告する場合、ユーザー名・SID・プロファイル名は伏せる。

```powershell
$PSVersionTable.PSVersion
[Environment]::Is64BitProcess
whoami /user
Get-ExecutionPolicy -List
```

この確認は起動許可を出さない。拒否や警告があれば停止する。ポリシー・Defender・SmartScreen・信頼ストアの変更、取得元情報の削除、Unblock-Fileは行わない。

## 自動化する起動前検査に必要な範囲と未完成事項

専用ユーザーを利用する合意後、通常版の既存チェックを利用して次を最小限の検査入口へまとめる。真偽値や自己申告だけで安全と判定しない。

- 現在のユーザーが確認済みの検証用ユーザーで、管理者権限なしであること。実KnownFolderを使い、ローカルNTFS・所有者・祖先リンク・共有パスを検査する。
- 初回だけ、そのユーザーの既知6保存先（TaskPilot、TaskPilot4、TaskPilot4Logs、TaskPilot4LegacyBackups、TaskPilot.storage.lock、TaskPilot4.storage.lock）が存在しないことを内容を開かず確認する。既存状態があれば停止し、削除・名前変更しない。再起動のたびに「初回」として検査せず、本人が確認した専用ユーザーとの対応を維持する設計が必要。
- 通常版の対象コミット・合格した必要テスト・同梱一覧・全ファイルのハッシュ・固定依存を照合する。ハッシュだけを発行者認証とみなさない。
- EXE/DLL/外部スクリプトの取得元とOSによる許可を確認する。通常EXEと同じ固定ps2exeホストによる無害な合成プログラムで、外部スクリプト/モジュールを読み込めるか実測する。
- ユーザー/パッケージの検査だけではPublicや外部アプリを隔離した証明にならないことを結果にも示す。

旧`tools/Test-TaskPilotAcceptancePackage.ps1`は専用パッケージとIndependentTestModeSupported=trueを要求するため、そのまま使用できない。旧検査を無効化してREADYにすることはしない。通常版の最小検査入口と対象PCでのホスト確認はまだ完成していない。

## 検証結果・開始可否・その後の操作

今回はソース調査と文書更新のみ。アプリコードは未変更なので、新しいEXE/ZIPを作らず、通常版の回帰試験も再実行しない。[直近のWindows Server CI](https://github.com/daiki0902-chiba/TaskPilot/actions/runs/45184776656)はコードd6a1dedに対する履歴で、通常8群・共通27件・追加保存8件等が合格、内部1項目SKIP。これを今回の新規実機結果に換算しない。[今回の記録](../verification/no-vm-feasibility-20261123.json)を参照。

**現在はNOT_READY。普段と同じWindowsユーザーでの完全隔離も、専用ユーザーによるWindows 10/11実機操作も未検証。** 専用ユーザーの採用確認、上記の最小起動前検査、取得・ホスト互換性の確認が残る。一般向けEXE/ZIP公開停止は維持する。

条件成立後の操作は「本人限定の検証資材を取得→検査→同じ通常版を起動→架空タスク・サブタスク・工数・通知・月次・Excel・保存・バックアップ・復元・再起動を確認→必要な画面とエラーだけを報告」とする。既存業務データ・プロファイル全体・他アプリのログは収集しない。終了後も業務ユーザーのデータや検証ユーザーを自動削除しない。現時点ではEXEの取得・起動コマンドは提示しない。
