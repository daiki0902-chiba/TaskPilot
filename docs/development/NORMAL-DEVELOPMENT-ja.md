# 通常版中心の最小開発構成

2026-11-23方針変更。唯一の製品は`TaskPilot.ps1`から生成する通常`TaskPilot.exe`。PowerShell 5.1・WinForms・SQLiteを維持し、データは本人のPC内へ保存する。main・実ユーザーデータは変更しない。公開停止を維持し、有料証明書の購入を前提にしない。

## 依存関係と整理

| 対象 | 調査結果と扱い |
| --- | --- |
| `TaskPilot.ps1`、`Runtime/TaskPilot.Runtime.ps1`、`Adapters/` | 通常版の入口と共通GUI。タスク、サブタスク、工数、通知、カレンダー、定期、月次、Excelを維持 |
| Storage・Migration・Protection、`Codec/`、`schema/` | SQLite、移行、バックアップ・復元に必要。削除しない |
| `Adapters/TaskPilot.GuiIsolation.ps1` | 名前にIsolationがあるが通常版のログ・Excel・ファイル置換にも必要。削除しない |
| `Runtime/TaskPilot.TestSandbox.cs`と同梱DLL | 通常起動ではロードしないが、現在のビルド契約・同梱一覧・共通境界検査が依存。今回は維持し、通常ビルドのDLLを検査にも再利用 |
| 独立モードの起動引数、受入・ローカル専用入口 | 既存の起動拒否を維持。新機能・新しい製品形態を追加しない |
| `acceptance/`、`local-validation/`のGUI生成物・ビルド・検査 | 通常版から参照されない追加入口。ソースを凍結し、既定CIから専用ビルド・重複回帰試験を除外。生成GUIを通常改修のたびに更新しない |
| 依存ロック、同梱一覧、ImportExcel/EPPlus・ライセンス・対応ソース | 通常版にも必要。依存固定・整合性・再配布条件の検査を維持 |

DBの用途タグ、未知スキーマ拒否、保存境界の検査、トランザクション、競合検出、二重起動対策、移行前バックアップ、元データを残す復元、障害ログは維持する。旧テスト領域や既存DBの削除・自動変換はしない。

ソースの一括削除や共通APIの改名はしない。専用入口と共通保護コードの依存を分離する必要が生じた時点で、小さな変更として検証する。

## 開発サイクルとテスト選定

依頼された変更を調査→通常版を修正→影響する群を選択→重要な回帰試験→通常版を1回だけ内部ビルド→条件成立後にクリーン環境でGUI確認、と進める。

```powershell
# 一覧のみ。アプリやテストを起動しない
.\Test-TaskPilotCommercial.ps1 -ListSuites
# GUIタスクの軽微な変更の例。実行した群だけを結果に記録
.\Test-TaskPilotCommercial.ps1 -Suite GuiTasks,GuiIntegration -DependencyRoot C:\TaskPilotBuild\deps-1
# 保存・移行・復元など重要な変更では全8群
.\Test-TaskPilotCommercial.ps1 -DependencyRoot C:\TaskPilotBuild\deps-1
```

| 変更範囲 | 基本の検証 |
| --- | --- |
| 文書だけ | リンク・差分確認。アプリの再ビルドは不要 |
| タスク・集計・操作 | 対応する`GuiTasks`・`GuiDomains`・`GuiOperations`と`GuiIntegration` |
| 通常の起動・アダプター接続 | `GuiStartup`・`GuiIntegration`、公開停止検査 |
| SQLite・移行・保存・バックアップ・復元・共通境界 | 全8群と共通の追加保存8件・境界27件（リンク/祖先境界80項目を内包）。変更した復旧機構の検査を追加 |
| ビルド・依存・同梱 | `Packaging`、依存照合、通常版の内部ビルド1回 |

既定の手動実行は全8群を維持。`-Suite`は選択機能であり、変更ファイルからの自動選択は実装しない。未選択の群は未実行、SKIPはSKIPとして残す。重複名・大文字小文字だけ異なる重複も拒否する。

今回のCIは編成と共通DLLの試験方法が変わるため、通常8群・旧保存回帰・公開停止12項目・ハンドル8項目・追加保存8件・共通境界27件を1回実行する。通常版のビルドは1回。特別な版のビルドは0回。受入固有の693検査や専用ホスト検査は通常版の合格証拠に転用せず、今後その凍結コードを変更する場合だけ検討する。レポートのみをActionsへ保存し、手動実行でもEXE・配布ZIPをアップロードする入口は設けない。

## ローカル実機確認の最小方式と阻害要因

専用アプリモードを増やさず、業務データのない新規Windows 10/11 VMで通常版の既定保存先を使用する。VMのユーザー保存先はホスト側の本番データ領域とは別である。ホストの共有フォルダー・追加ディスク・転送連携は接続しない。架空データだけで確認する。単に`LOCALAPPDATA`を書き換えたり、同じPCでユーザーだけを切り替えたりして完全分離したとは扱わない。

現時点は**NOT_READY**。最小限、次の順に確認する。

1. 開発者がクリーンVMを準備できるか、Windowsの利用権・仮想化・共有なしの構成を確認する。本番データをVMへ持ち込まない。
2. 通常版の固定ps2exeホストが、対象Windowsの既存保護設定のまま外部Runtime・GUI・SQLite・Excelモジュールをロードできるか確認する。まず無害な合成プログラムで確認し、実アプリを試験に使わない。[ホスト調査と未検証事項](NORMAL-HOST-COMPATIBILITY-ja.md)を参照。署名・取得元・実行ポリシーの拒否を解除して解決しない。
3. 対象コミットと一致する通常版の内部ビルド・依存ハッシュ・必要な試験結果を揃え、そのVMの旧データ不存在を起動前に確認する。従来の受入パッケージ検査は専用構成を前提とし、`IndependentTestModeSupported=true`も要求するため、現在の通常版へそのまま使えない。既存検査を弱めず、通常版の既存ハッシュ一覧・依存照合・取得元検査・既知6保存先の不存在確認を使う最小の検査入口へ整理する作業が残る。
4. 以上が成立してから引数なしの通常版でGUI・通知・Excel・保存・復元を確認する。Windowsの警告や検査不合格が出たら停止する。現時点で実機起動の許可やダウンロード手順は案内しない。

通常版のファイル選択はユーザーがアクセスできる範囲を扱うため、同じ業務ユーザー内での隔離を保証する設計ではない。親ホストのRSAプロトコルや別製品版を完成させることは、このVM方式の前提にしない。OS保護・実行ポリシー・信頼ストアの変更、有料証明書の購入、EXE/ZIPの一般公開は行わない。
